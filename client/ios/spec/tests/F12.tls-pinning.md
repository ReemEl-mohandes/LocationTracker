# F12 — TLS Certificate Pinning (characterization)

`APIClient` URLSession delegate + `perform` URL guard. Services: this **is** the S3 transport
seam; the pin set comes from `AppConfig`. Config injected so tests supply their own fingerprints.

## Service / rules (challenge handling)

### F12.1 Publicly-trusted cert — happy
- **Given** a server-trust challenge that passes `SecTrustEvaluateWithError`
- **Then** default handling is used (a real CA cert would just work); pin set not consulted.

### F12.2 Self-signed cert matching a pin — happy
- **Given** evaluation fails, leaf SHA-256 == a value in `pinnedCertificateSHA256`
- **Then** the challenge is accepted with a credential built from the trust; `rejectedFingerprint`
  cleared.

### F12.3 Self-signed cert not matching — error
- **Given** evaluation fails, leaf SHA-256 **not** in the pin set
- **Then** the challenge is cancelled; `rejectedFingerprint` set to that fingerprint (for F1.12).

### F12.4 No leaf certificate — error
- **Given** the chain has no leaf
- **Then** the challenge is cancelled.

### F12.5 Non-server-trust challenge — edge
- **Given** an auth method other than server trust
- **Then** default handling.

## Service / rules (URL guard)

### F12.6 Plain http rejected — error
- **Given** the configured server URL is `http://…`
- **When** `perform(...)`
- **Then** `APIError.badServerURL` is thrown; no request is made.

### F12.7 Fingerprint format — edge
- The comparison is case-insensitive on the uppercased colon-separated SHA-256 string, matching the
  `openssl x509 -fingerprint -sha256` format stored in `AppConfig`.
