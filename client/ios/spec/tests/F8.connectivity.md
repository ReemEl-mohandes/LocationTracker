# F8 — Connectivity & Offline/Online Notices (characterization)

`UploadQueue` reachability handling. Services: **S7 Reachability**, **S3 LocationAPI** (flush),
**S8 Notifying**, **S4 TokenStoring**, **S10 Clock**.

## Controller

### F8.1 Reconnect flushes and notifies — happy
- **Given** was offline, an offline notice had fired, N points queued
- **When** `Reachability.onChange(online:true)`
- **Then** `notBefore` cleared; `flush()` runs; if it made progress, `Notifying.post` "Back online"
  with `uploaded = before - after`.

### F8.2 Reconnect with no prior offline notice — edge
- **Given** was offline only briefly, no offline notice fired
- **When** back online
- **Then** flush runs; **no** "Back online" notice (only paired with a prior "Offline").

### F8.3 Drop schedules a delayed offline notice — happy
- **Given** online → `onChange(online:false)`
- **Then** an offline notice is scheduled after `offlineNoticeDelay (60 s)`.

### F8.4 Short dropout suppressed — edge
- **Given** offline, then online again before 60 s elapse
- **When** the delayed check fires
- **Then** because `wasOnline == true` again (or `offlineSince` changed), **no** "Offline" notice.

### F8.5 Offline notice requires a session — edge
- **Given** offline ≥ 60 s but `TokenStoring.load() == nil`
- **Then** no "Offline" notice (nothing to upload; user is signed out).

### F8.6 Offline notice content — happy
- **Then** the posted body includes the current pending count (e.g. "…(37 points so far)…").
