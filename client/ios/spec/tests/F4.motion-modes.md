# F4 — Motion-Driven Accuracy Modes (characterization)

`handleMotion` + `applyMode`. Services: **S2 MotionProviding** (in), **S1 LocationProviding**
(applyMode out), **S10 PowerState** (in). The mapping is pure and should become **Model**.

## Model / rules (mode selection)

### F4.1 Mode by motion state (moving, not low power) — happy
- automotive → accuracy `bestForNavigation`, activityType `.automotiveNavigation`
- onFoot / cycling → accuracy `best`, activityType `.fitness`
- unknown → accuracy `best`, activityType `.other`
- **All** moving modes use `distanceFilter == distanceFilterMeters (10)`.

### F4.2 Low Power Mode drops a notch — edge
- **Given** `PowerState.isLowPower() == true`
- **Then** automotive → `best`; onFoot/cycling/unknown → `nearestTenMeters`.

### F4.3 Stationary mode overrides motion — edge
- **Given** `applyMode(stationary:true)`
- **Then** accuracy `hundredMeters`, filter `stationaryDistanceFilterMeters (50)`, activityType
  `.other`, regardless of `motionState`.

## Controller (handleMotion)

### F4.4 Low-confidence ignored — edge
- **Given** an activity with `confidence == .low`
- **When** `handleMotion`
- **Then** `motionState` unchanged; no `applyMode` call.

### F4.5 Change to a moving state — happy
- **Given** confident `.automotive`
- **When** `handleMotion`
- **Then** `motionState == .automotive`, `lastMovementAt` refreshed to now (via **S10 Clock**),
  `applyMode(stationary:false)` called.

### F4.6 Duplicate state — edge
- **Given** current state already `.automotive`, another confident `.automotive`
- **Then** no-op (guarded by `state != motionState`).

### F4.7 Change to stationary while in saving mode — edge
- **Given** `isStationary == true`, confident `.stationary`
- **Then** `lastMovementAt` **not** refreshed (not moving); `applyMode` not forced to full
  (condition `state.isMoving || !isStationary` is false). Recorded as-is.
