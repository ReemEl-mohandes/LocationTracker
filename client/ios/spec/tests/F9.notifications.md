# F9 — Trip-End & Tracking Notifications (characterization)

`UploadQueue.tripEnded`, `Notifier`, `TrackingWatchdog`. Services: **S3 LocationAPI** (trip fetch),
**S8 Notifying**, **S6 KeyValueStore** (activeTripId, notified-trip ids, cooldowns),
**S10 Clock**.

## Controller (trip-end detection)

### F9.1 Active trip changes → summary — happy
- **Given** stored `activeTripId == 7`
- **When** a batch response returns `activeTripId == 8` (or `null`)
- **Then** `tripEnded(7)` runs: `LocationAPI.trip(7)` fetched; if `!isActive`, `Notifying.post`
  "Trip recorded" with distance/duration/max speed; stored `activeTripId` updated to the new value.

### F9.2 Trip still active on fetch — edge
- **Given** `trip(7)` comes back `isActive == true`
- **Then** no notification (guard `!trip.isActive`).

### F9.3 Trip discarded by server (404) — edge
- **Given** `trip(7)` throws (server discarded it as noise)
- **Then** no notification; no crash (`try?`).

### F9.4 One summary per trip — edge
- **Given** trip 7 already notified (id recorded in **S6**)
- **When** `tripEnded(7)` again
- **Then** no duplicate notification.

## Controller (tracking on/off)

### F9.5 trackingOn cooldown — happy/edge
- **When** `Notifier.trackingOn()`
- **Then** posts "Location sharing is on" **at most once per 10 min** (cooldown in **S6**);
  a call within the window is suppressed.

### F9.6 trackingOff reasons — happy
- `pauseByUser` → "you turned it off"; authorization denied → "turned off in Settings"; server
  sign-out while tracking → "you were signed out…". Each posts with the `tracking-state` id
  (replacing the previous).

## Service (watchdog)

### F9.7 Watchdog re-arms — happy
- **When** `arm()`
- **Then** `Notifying.scheduleAfter("tracking-stopped", watchdogDelay (1200 s), …)` — replacing any
  pending one and clearing a delivered one. Repeated arming pushes the fire time out.

### F9.8 Watchdog disarmed on stop — happy
- **When** `stop()` → `disarm()`
- **Then** the pending "tracking-stopped" notification is cancelled.

### F9.9 Foreground presentation policy — edge
- Trip and connectivity notifications show as banners in the foreground; "tracking on" does not
  (`Notifier.showsInForeground`).
