# F11 — Queue Ownership (characterization)

`UploadQueue.claim` / `clear` and the app-level sign-in/out wiring. Services: **S6 KeyValueStore**
(owner key), **S5 PointStore**.

## Controller

### F11.1 Same user re-claims — happy
- **Given** owner key == user A, backlog present
- **When** `claim(for: A)`
- **Then** backlog **kept**; owner stays A.

### F11.2 Different user claims — edge (critical)
- **Given** owner key == user A, backlog present
- **When** `claim(for: B)`
- **Then** `clear()` runs (backlog dropped, owner removed), then owner set to B. One user's history
  never uploads under another's session.

### F11.3 First claim — happy
- **Given** no owner key
- **When** `claim(for: A)`
- **Then** backlog kept; owner set to A.

### F11.4 clear empties everything — happy
- **When** `clear()`
- **Then** pending emptied, `activeTripId = nil`, `lastUploadAt/Summary/error` reset, owner key
  removed, persisted.

## App wiring (composition root)

### F11.5 onSignedIn claims — happy
- **When** `SessionStore.onSignedIn(profile)`
- **Then** `queue.claim(for: profile.id)`.

### F11.6 Explicit sign-out clears — happy
- **When** `onSignedOut(explicit:true)`
- **Then** `tracker.stop(flushRemaining:false)` **and** `queue.clear()`.

### F11.7 Server expiry keeps the backlog — edge (deliberate)
- **When** `onSignedOut(explicit:false)`
- **Then** `tracker.stop(flushRemaining:false)` but **no** `queue.clear()` — the points are still
  that user's and upload after they sign in again; a "tracking off (signed out)" notice is posted
  if it was tracking.
